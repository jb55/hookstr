01Concepts & roles

Two binaries, one immutable event per delivery.

hookstr splits webhook delivery from webhook consumption so a flaky consumer never makes a provider give up. There are two halves:

BinaryRuns whereDoes what
hookstrd always-online box (VPS), behind a TLS proxy Accepts webhook POSTs, persists each as a signed kind:3003 nostr event in nostrdb, and serves them back over an authenticated, read-only relay.
hookstr the consumer's machine (laptop, box behind a tunnel) The drain: syncs down everything it missed, replays each delivery as a byte-exact local HTTP request, then follows in realtime.

Each delivery becomes one immutable, signed event: the raw body as content (base64 + an encoding tag when it isn't UTF-8), the ingest path in a path tag for replay routing, the provider name in an indexed t tag, and one header tag per preserved header. Nothing is ever deleted — the store is the source of truth, and negentropy (NIP-77) reconciles over the full set, which is what makes "catch up after being offline for a week" a non-event.

Two keypairs. The server has its own keypair; it signs every webhook event. The drain has its own keypair; its pubkey goes on the server's NIP-42 allowlist so only it can read. You generate the drain key first (hookstr init), because the server config needs its pubkey.

02Build the binaries

One Rust workspace; two binaries fall out of it.

$ git clone https://github.com/jb55/hookstr
$ cd hookstr
$ cargo build --release
# → target/release/hookstrd   (the daemon)
# → target/release/hookstr    (the drain CLI)

Copy hookstrd to the server and hookstr to the consumer. They share no state and never talk except over the relay's websocket. cargo test --workspace runs the full end-to-end suite (real daemon + real drain, in-process) with no external services.

03Server: hookstrd

The always-online half. Do this on the VPS.

1 — Generate the server keypair

keygen is on the CLI binary, but the key it prints can be used for either side. Make one for the server and write the nsec to a file (config never holds the secret inline — only a path to it):

$ hookstr keygen
nsec:   nsec1qy2…
pubkey: 8f2a…

$ umask 077
$ hookstr keygen | awk '/nsec/{print $2}' > /var/lib/hookstr/server.nsec
The server's pubkey doesn't need to go anywhere — the drain trusts events by signature, not by an allowlist.

2 — Get the drain's pubkey

You need the drain's pubkey for the allowlist. Either jump to §06 and run hookstr init on the consumer first, or generate one now with hookstr keygen and hand its nsec to the consumer later. Keep the hex pubkey handy.

3 — Write hookstrd.toml

See §09 for the full table. By default one port serves both ingest and the relay (listen_addr); the advanced split is below.

db_path      = "/var/lib/hookstr/ndb"
mapsize      = 34359738368            # 32 GiB — store-everything, size it generously
listen_addr  = "127.0.0.1:8080"       # one port: webhook ingest + relay ws (proxy fronts this)
nsec_path    = "/var/lib/hookstr/server.nsec"
drain_pubkey = "9b3d462694fc29e5…"     # the DRAIN's pubkey, hex — NIP-42 allowlist

# Per-provider ingest secrets. Keep this table LAST: a TOML table swallows
# every key beneath it. Each value must be unique — the token names its provider.
[ingest_tokens]
acme   = "long-random-secret-1"
stripe = "long-random-secret-2"

4 — Run it

$ hookstrd --config /etc/hookstr/hookstrd.toml
hookstrd listening on 127.0.0.1:8080 (webhook ingest + relay ws)

--config defaults to hookstrd.toml in the working directory. Set RUST_LOG=info (or debug) for logs. A minimal systemd unit:

[Service]
ExecStart=/usr/local/bin/hookstrd --config /etc/hookstr/hookstrd.toml
Environment=RUST_LOG=info
Restart=always
User=hookstr
Bind to localhost. The listener is plaintext and expects the reverse proxy to terminate TLS. Don't expose 8080 to the internet directly.

04Reverse proxy & TLS

One port; hookstrd sorts ingest from relay itself.

hookstrd serves ingest and the relay on the one listen_addr and demuxes them by the Upgrade header — a websocket upgrade goes to the relay, everything else (POST /ingest/*, a browser GET /) to the ingest router. So the proxy just terminates TLS and forwards everything; no header-routing of its own:

hooks.example.com {
        reverse_proxy localhost:8080
}
Advanced — separate binds. Set ingest_addr + relay_addr instead of listen_addr to put the two on their own listeners. The relay can then bind a private interface — e.g. a WireGuard address — and stay off the public internet entirely, while only ingest faces the proxy. Set one form or the other, never both. This mode wants the classic two-handle proxy split (/ingest/* → ingest, everything else → relay).
nginx: raise the read timeout. The drain holds an idle websocket open while following. nginx's default proxy_read_timeout (60s) resets it every minute. The drain sends a keepalive ping every 25s to survive that, but set proxy_read_timeout 3600s; and the usual Upgrade/Connection headers on the relay location anyway.

05Registering providers

One URL per provider; the token is the whole auth story.

For each provider, register a URL of the shape:

https://hooks.example.com/ingest/<token>/<any/path/you/like>

e.g. register …/ingest/long-random-secret-1/acme/events with Acme. On the wire:

  • The token alone authenticates the delivery and names its provider (that's why token values must be unique). A wrong token is a 404, indistinguishable from a missing route — probing reveals neither which providers exist nor their paths.
  • Everything after the token is free-form. It's echoed into the event's path tag and becomes the replay routing key (§07).
  • A successful, durably-stored delivery gets a 204. A 5xx means the store failed — the provider should retry. Any other webhook auth (an x-signature HMAC) is preserved and re-validated by your consumer on replay; hookstrd doesn't check it.
Rotating a leaked URL: change (or remove) that provider's line in [ingest_tokens], restart hookstrd, and re-register the new URL. The other providers are untouched.

06Client: the drain CLI

The consumer half. Do this on the machine that handles the webhooks.

1 — hookstr init

First-run setup. It generates the drain keypair (written 0600 next to the config), writes a starter config, and prints the pubkey for the server's allowlist. Pass the relay URL:

$ hookstr init wss://hooks.example.com
wrote keypair /home/you/.config/hookstr/drain.nsec
wrote config /home/you/.config/hookstr/config.toml

pubkey: 9b3d462694fc29e57ff202a8e8f4caa68c668e5034ac1c00c7c21dadf92a2aa0
        ^ add this to hookstrd's drain_pubkey allowlist

The config lands at $XDG_CONFIG_HOME/hookstr/config.toml (falling back to ~/.config/hookstr/); the local mirror db and replay state go under ~/.local/share/hookstr/. init refuses to overwrite an existing config, and keeps an existing keypair if one is already there (it may already be on the allowlist).

2 — Put the pubkey on the allowlist

Copy that pubkey into the server's drain_pubkey (§03) and restart hookstrd. Until then the relay refuses REQ/sync from this key — a permanent refusal the drain won't retry.

3 — Review the config

The config holds the durable sync identity — relay, keys, local db. init already filled it in. Nothing target-related lives here: where the drain delivers is a per-run flag (next step), specific to the consumer it feeds rather than to the sync relationship the config describes.

relay_url = "wss://hooks.example.com"
db_path   = "/home/you/.local/share/hookstr/ndb"
redb_path = "/home/you/.local/share/hookstr/replays.redb"
nsec_path = "/home/you/.config/hookstr/drain.nsec"

4 — hookstr drain

$ hookstr drain --target http://localhost:3000/webhooks
reconciled 42 missing webhook event(s)
drain complete: 42 replayed, 0 failed, 0 with no target (42 stored total)
following: replaying new webhooks as they arrive

--target is where deliveries replay — a per-run flag, not config, since it's specific to the consumer this drain feeds. That connects, AUTHs (NIP-42), negentropy-reconciles the backlog, replays it oldest-first, and then follows — each new webhook replays in under a second while connected, and a dropped connection redials with backoff. Useful additions (each still takes --target):

Add to the commandEffect
--once Catch up + replay, then exit instead of following. Cron-style.
acme stripe (positional) Scope to specific providers (matched on the indexed t tag). Empty = all — so one hookstrd feeds several consumers, each a scoped drain with its own --target.
[targets] (in config) Pin specific ingest paths to other consumers; these win over --target (§07).

Replay state (attempt counts, backoff) is client-local in redb, keyed by event id. A target that's down just means backoff and retry — the events are already durable on the server, so nothing is lost. Replay is at-least-once: your handler must dedupe on the provider's delivery-id header, which makes crash-mid-replay safe.

07Replay routing

From ingest path to local URL.

The event's path tag mirrors everything after the token in the ingest URL. By default a delivery replays to {--target}/{path}:

# provider POSTs to:
https://hooks.example.com/ingest/<token>/acme/events

# with --target http://localhost:3000/webhooks, replays to:
http://localhost:3000/webhooks/acme/events

When a consumer's route doesn't mirror the ingest path — a second app on another port, a different route shape — add a [targets] table to the config keyed by the exact path. An explicit override always wins over --target:

[targets]
"acme/events" = "http://localhost:4000/hooks"   # this path only

With some routing configured, a delivery whose path isn't covered — no --target base and no matching override — is left unreplayed (counted as "no target") so a later run or config change can pick it up; it's never dropped. But a drain started with neither a --target nor any [targets] entry has nowhere to deliver anything, so it errors out immediately rather than syncing a backlog it can't route.

08CLI reference

hookstr <command> — the drain binary.

CommandArgs / flagsWhat it does
init [relay_url] --config <path> First-run setup: generate the drain keypair, write a starter config, print the allowlist pubkey. relay_url is optional (a placeholder is written if omitted).
drain [providers…] --once, --target <url>, --config <path> Sync, replay the backlog, then follow. --target sets the replay base (deliveries POST to {target}/{path}); --once exits after catch-up; positional providers scope by t tag.
keygen — Print a fresh nsec + hex pubkey. Usable for either side.

Config defaults to $XDG_CONFIG_HOME/hookstr/config.toml. Both binaries log via tracing; the drain defaults to info, and RUST_LOG overrides either.

09Config reference

Every key in both TOML files. Paths are used verbatim — no ~ expansion.

hookstrd.toml (server)

KeyMeaning
db_pathrequired nostrdb directory. Created if missing.
mapsizerequired LMDB map size in bytes — the ceiling on total stored bytes. Size it generously (e.g. 34359738368 = 32 GiB); nothing is ever pruned.
listen_addrone of Combined mode (default): one plaintext listener for ingest + relay ws, e.g. 127.0.0.1:8080. Front with TLS. Set this or the pair below.
ingest_addr
relay_addr		one of Separate mode (advanced): distinct listeners for ingest and the relay ws. Lets the relay bind a private interface (e.g. WireGuard) off the public net. Set both, and not listen_addr.
nsec_pathrequired Path to a file holding the server nsec. The key signs every webhook event.
drain_pubkeyrequired The drain's 64-char hex pubkey — the sole entry on the NIP-42 read allowlist.
[ingest_tokens]required Table of provider = "token". Values must be unique. Keep it last in the file.

config.toml (drain)

KeyMeaning
relay_urlrequired hookstrd's relay endpoint, e.g. wss://hooks.example.com.
db_pathrequired Local mirror nostrdb — negentropy needs the full local set here.

nsec_pathrequired File holding the drain nsec; its pubkey is on the server's allowlist.

The replay base (--target) and provider scope (positional args) are not config keys — they're per-run flags on drain.

10Operations

What breaks, and what happens when it does.

FailureOutcome
ingest box downProvider retries per its own schedule. This is the only failure surface a provider ever sees.
nostrdb write failsIngest answers 5xx → provider retries. A 204 is only ever sent after a durable commit.
drain crashes mid-replayAt-least-once + your dedupe on the delivery id → safe.
duplicate provider deliveriesDistinct events; your consumer dedupes on the delivery id.
replay target downredb records the failure and backs off; events are already durable, so the next drain retries.
unauthed / wrong-key ws clientNIP-42: no REQ or sync until AUTH from the allowlisted pubkey. A wrong key is a permanent refusal.
ingest URL leaksRotate that provider's token, restart, re-register. Others unaffected.

Storage grows monotonically — nothing is deleted, by design. Webhook bodies are a few KB each, so even a million deliveries is single-digit GB; watch mapsize headroom the way you'd watch any append-only log. Full design rationale, including the reasoning behind each constraint, is in SPIKE.md.
